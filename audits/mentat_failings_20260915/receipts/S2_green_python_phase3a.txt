Change (mentat/tools/export_raw_contribution_warehouse.py):
  * new helpers missing_columns_by_table() and warn_missing_contract_columns()
    beside contract_column_order().
  * when any table's placement reports missing block members, the export
    receipt gains a TOP-LEVEL key `missing_contract_columns` = {table: [names]},
    listing only the tables with gaps. The key is OMITTED entirely when
    nothing is missing, so a migrated database's receipt keeps its old shape.
  * one stderr line per affected table:
      warning: <table> lacks contract columns <names>; run init_schema() from
      mentat/R/schema.R before treating this export as complete
  * `status` STAYS "succeeded". tools/parallel/Start-MentatResilientIndustryReports.ps1
    keys its exit-code contract on that field (HANDOFF/PACKET), and the rows
    written are a complete record of what the database actually holds, so a
    schema gap must not become a pipeline outage.
  * BOTH receipt paths are covered. The reuse ("fast") path builds its own
    receipt dict and never computes a placement, so it would have silently
    dropped the warning on every rerun - the case an operator hits most
    often. It now recomputes the gap from the schema the stored manifest
    already carries, giving the same answer as the full path.
