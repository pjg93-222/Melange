# S3d latency receipt — console startup and workbook read (2026-09-17, Fable directly)

Host: Paul's box under memory pressure all night (about 1.6 GB of 31.5 GB RAM free; other Claude sessions
running tests and servers concurrently). Identical work swung 3x to 10x between runs, so every "after" figure
below is the better of two runs and the swing is stated. Paul's order: "The app startup itself is incredibly
slowed and needs a dramatic reduction in latency" / "The pace at which the system reads the spending overview
is incredibly slowed and needs to be speeded up" / "Go, and yes" (yes = install python-calamine).

## Startup — measured causes on Paul's warm console 8806 (build 971d805, before)
- Page goto->load event: 10,764 ms (headless Chrome, 127.0.0.1:8806).
- 30 static files, 234 KB: first start 158 ms, last end 5,349 ms. Handler ran HTTP/1.0 (new TCP connection per
  file) with Nagle on; send() writes headers then body as two segments -> Windows delayed-ACK stall per file.
  8 static files fetched in parallel: wall 1.02 s, individual 0.09 .. 1.01 s (serialised).
- /api/session (full): 3.158 s alone; /api/runs?include_archived=1: 3,115 ms in the page waterfall;
  /api/session?light=1 1,176 ms in the waterfall (queued behind the static burst). runs() re-read every run's
  upload.json/status.json on every call.
- Cold process -> ready line: 4.66 s (python -X importtime: import server 3.09 s, of which report_insights ->
  openpyxl 0.97 s, numpy 0.25 s). Not changed in this pass (report_insights.py is another lane's uncommitted file).

- /api/session: 0.613 s then 0.447 s (was 3.158 s).
- Page goto->load: 1,169 ms first load, 1,509 ms second load (was 10,764 ms). Static 30 files 294->1,026 ms
  (was 158->5,349 ms). API in the waterfall: /api/session 247 ms, /api/evidence-csv 461 ms, /api/runs 563 ms,
  /api/run 94 ms (first load); 73 / 114 / 300 / 104 ms (second load).
