Collect only after a router was replaced, keep one work index for a whole search request, and say that a request still running can defeat the memory saving

Three findings of the Opus re-check of v4 and of the live panel on the sidecar that runs it.

The prewarm's one garbage collection ran at a start as well as after a publish. At a start nothing has been replaced, so it freed nothing, and it held every request thread for 10.1 s on the live heap (gc_ms 10,145.99 on /api/staffer-performance), ahead of the 62 s prewarm that otherwise blocks nobody. _release_replaced_router now sets a flag, under the prewarm lock, when it is given a router that was actually replaced (not None, not the router just published), and _prewarm collects only when it finds the flag set, clearing it in the same step, once, before its first build. A prewarm abandoned before it builds neither collects nor clears it, so the prewarm that does build collects for every swap since the last collection. A prewarm that follows no replacement, the first one after a start, collects nothing and has no gc_ms.

Distinct and independent alternatives call ClosenessRoutes.route once per pass, and each call asked the router's table for its work index. A release that landed between two passes of a request still running on the replaced router therefore made the next pass build the whole index again (finding A1; tens of seconds on the live records, for one request, on a router nothing else will use). AdvocacyRouter.route_many now opens a request scope, a contextvar (staffer_closeness_routes.request_work), around distinct_routes and around the Yen loop of the other objectives, and ClosenessRoutes.index gives a request the index it took first for every later pass. A scope that is open already is the request's own, and it closes however the request ends. ClosenessRoutes also has a released flag, set by release() and never cleared. A released router stores no index and no hop-row cache it builds, and an index whose build was still running at the release is not put back into the emptied table (the re-check watched the old router's prewarm build put it back, which kept the replaced router's whole index alive). It still answers every request that reaches it: a request with a scope shares one index and one hop-row cache among its passes, one without builds its own. release_search_state now creates the search object of a router that has none yet, so that router is released as well. No answer changes: every new test compares the answer with the same request on an untouched twin router.

The README and two comments in staffer_live_service.py said that the replaced router's indexes and the new router's "are not resident together". That is only so once no request is still running on the replaced router: such a request keeps its index until it ends, and no collection frees what it still refers to. They now say that, and that a start runs no collection.

Tests. test_staffer_prewarm.py (35 tests): a prewarm at a start runs no collection and has no gc_ms; the prewarm after a replacement runs one before its first build and the next one none; abandoned prewarms collect nothing and the one that builds collects for all the swaps; only an actual replacement asks for a collection, even when the release itself fails; a request waiting on the replaced router's in-flight build is answered and the finished build is not put back (the re-check's part 3). The two tests that had the released router keep what it built now expect it to keep nothing. test_staffer_request_work_index.py (new, 17 tests): the re-check's scenario for distinct and independent (a release between the passes: no build, one index object, the twin's answer), with a negative control that removes the scope (the next pass builds again), a ranked request, a request that starts on a released router (one index and one hop-row cache for all its passes, none kept), an in-flight build that finishes after the release, the scope per thread, nested, closed on an error and opened by route_many exactly where it should be, and a short run of the stress test.
