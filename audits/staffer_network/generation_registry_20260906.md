## Notes and known limitations

- A second, trailing `vN` token (e.g. `..._v5_verification_v2`) is dropped rather than kept in the family string, so that directory and its plain `..._v5_verification` sibling can be compared for recency as the same lineage. The side effect: both then report the identical (family, stamp, version, role) tuple in the table below even though they are two different directories -- always key off the `Name` column, never off family/stamp/version/role alone, when mapping a row back to disk.
- Only `vN` tokens are recognized as version markers. Alternate iteration markers (generationN, checkpointN, r2/r3, prev1, a trailing second _v2, _failed_*, _rebuild) stay embedded in the family string, so a directory carrying one becomes its own singleton family and defaults to ACTIVE via the trivial newest-of-family rule. Search the JSON for family strings containing `generation` or `checkpoint` to review these lineages by hand.
- Directories with no date stamp at all (schema/reference dirs, scratch dirs, `__pycache__`) are singleton families and default to ACTIVE the same way.
- `referenced_by` is capped at 10 matches per directory and stops scanning once 10 are found; `referenced_by_truncated_at_10=true` means there may be more.
- This script never deletes, moves, renames, or compresses anything. The `_inactive.txt` file is a candidate list for Paul's own review, not an action taken.
