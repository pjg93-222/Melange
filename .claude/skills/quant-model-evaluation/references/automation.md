# Automation and pipelines — quant-model-evaluation reference

> **Load when:** auditing a pipeline, scheduled refresh, build chain, dashboard feed or audit harness; reproducing a number from the commit it cites; checking that several implementations of one model agree; confirming that a background or scheduled job really finished; finding outputs that feed back into inputs. **Not for:** Monte-Carlo sufficiency and simulation V&V (`engineering-simulation.md`); citation integrity and claim ledgers (`citation.md`); data-use law and platform terms (`regulatory.md`); train/test leakage inside ML models (`machine-learning.md`, `scripts/leakage_audit.py`); honesty of the charts a pipeline feeds (`data-visualization.md`).
> Facts marked (as of DATE) are time-sensitive; re-verify before relying on them.

A model can be mathematically right and still wrong in use: correct code run on stale inputs, on the wrong data vintage, in a drifted environment, from a dirty working tree, or quietly falling back to a default. This module tests the machinery around the model. Many of its dynamic tests re-run the system; those are owner-gated (`RUNS-SYSTEM`). Every test starts with a read-only static pass. The renv, targets, uv and DataLad commands below follow each tool's documentation; none of those tools was installed on the build machine, so those commands were not run here (as of 2026-09-30).

## 1. Assumption map

| Assumption (class) | Where it usually hides | What breaks if it is false | Tests |
|---|---|---|---|
| Same code and inputs give the same outputs (COMPUTATIONAL) | unseeded or global generators; set and dict iteration; hash randomization; unsorted directory listings; parallel reductions; clock reads | run-to-run differences read as real change; unreproducible numbers | 2.1 |
| A step can be re-run safely (COMPUTATIONAL) | appends without de-duplication; in-place edits; outputs folded into the next cycle's inputs | drift, double counting, self-reinforcing loops | 2.2 |
| Inputs are fresh (DATA) | modification-time checks; partial refreshes; artifacts older than their upstreams | stale numbers shown as current | 2.3 |
| Inputs are the vintage the analysis claims (DATA) | latest-revised series in backtests; amendments replacing originals; filing lags | look-ahead bias; irreproducible history | 2.4 |
| The environment is pinned (COMPUTATIONAL) | no lockfile; lockfile out of sync; interpreter, OS and system libraries unrecorded | behavior changes after an upgrade with no code change | 2.5 |
| The cited commit works from a clean checkout (COMPUTATIONAL) | untracked modules; local edits; gitignored inputs; line-ending conversion | a green suite that proves nothing about the commit cited | 2.6 |
| Every copy of the model agrees (COMPUTATIONAL) | back-end engine, front-end mirror, report port, spreadsheet; constants copied as literals | surfaces disagree; overrides reach one copy only | 2.7 |
| Audit checks read the real artifact and can fail (COMPUTATIONAL) | checks on post-processed outputs; check-count gates; relaxed tripwires; fixtures regenerated by the code under test | false assurance | 2.8; `scripts/mutation_check.py` |
| Missing inputs fail visibly (DATA) | defaulting lookups, bare exception handlers, neutral multipliers, median fill, unmatched joins read as zero | silent degradation that looks normal | 2.9 |
| Every reported number is traceable (DATA) | no lineage record; hashes of normalized copies; numbers that live only in logs or chat | unverifiable claims | 2.10 |
| Every process is observable (COMPUTATIONAL) | long jobs with no progress events; logs overwritten each run | stalls unnoticed; completion inferred | 2.11 |
| A job that reports success landed its outputs (COMPUTATIONAL) | exit 0 with no writes; "complete" banners after a skipped step; jobs killed by restarts | stale outputs treated as fresh | 2.12 |
| Tuning does not overfit the evaluation (STATISTICAL) | one dataset used both to search and to accept; many looks, one reported | inflated performance | 2.13 |
| Concurrent jobs do not corrupt each other (COMPUTATIONAL) | two writers on one file; readers during a write; stale locks | truncated or mixed artifacts | 2.14 |

## 2. Tests

### 2.1 Determinism
- **Tests:** whether identical code and inputs give identical outputs.
- **Assumptions of the test itself:** the comparison ignores only fields meant to change (timestamps, run ids); any tolerance for floating-point reordering is stated before the run.
- **Run it:** static pass (read-only): look for unseeded or global generators (`np.random.seed`, bare `random.random()`, `default_rng()` with no seed, R `sample()` with no recorded `set.seed()` and `RNGkind()`), iteration over sets, `os.listdir` or `glob` results used without sorting, clock reads inside computations, and parallel reductions. Dynamic pass (owner-gated): run twice with the same seed into two folders, once more with `PYTHONHASHSEED` changed, and once with input rows shuffled; compare.
  ```python
  import hashlib, pathlib
  import numpy as np, pandas as pd
  def sha(p): return hashlib.sha256(pathlib.Path(p).read_bytes()).hexdigest()
  def compare_runs(dir_a, dir_b, key, rtol=1e-9):
      """Byte identity first; otherwise keyed numeric agreement after sorting (key must be unique)."""
      out = {}
      for pa in sorted(pathlib.Path(dir_a).glob("*.csv")):
          pb = pathlib.Path(dir_b) / pa.name
          if not pb.exists(): out[pa.name] = "MISSING in run B"; continue
          if sha(pa) == sha(pb): out[pa.name] = "byte-identical"; continue
          a, b = pd.read_csv(pa).sort_values(key), pd.read_csv(pb).sort_values(key)
          same = a[key].tolist() == b[key].tolist() and np.allclose(
              a.select_dtypes("number"), b.select_dtypes("number"), rtol=rtol, atol=0)
          out[pa.name] = "equal within rtol after sorting" if same else "DIFFERENT"
      return out
  ```
- **Pass criterion (fix before running):** byte-identical outputs, or keyed equality within the stated tolerance; shuffled input rows and a changed hash seed change nothing after sorting.
- **Failure signature:** ranks differ between two identical runs; outputs depend on file-listing order or the hash seed; a flaky test "fixed" by re-running it.
- **Source:** Goldberg (1991) on summation order; Luo et al. (2014) on flaky tests; Sandve et al. (2013).

### 2.2 Idempotence and feedback loops
- **Tests:** whether a step can be re-run without changing its result, and whether outputs quietly become inputs.
- **Assumptions of the test itself:** the read/write census covers every step, including manual and scheduled ones and spreadsheet writers.
- **Run it:** census each step's reads and writes from its code (paths opened, tables written), build a graph, and look for cycles. An intended cycle (a state file carried between cycles) must be declared and versioned. Dynamic check (owner-gated): run one step twice on the same inputs; outputs must be byte-identical and row counts must not grow.
  ```python
  import networkx as nx
  steps = [("collect", ["raw.csv"], ["clean.csv"]),                   # (step, reads, writes) from the census
           ("model", ["clean.csv", "priors.json"], ["scores.json"]),
           ("refresh", ["scores.json"], ["priors.json"])]
  G = nx.DiGraph()
  for step, reads, writes in steps:
      G.add_edges_from((r, step) for r in reads); G.add_edges_from((step, w) for w in writes)
  print(list(nx.simple_cycles(G)))       # any cycle: an output feeds a later input
  ```
- **Pass criterion (fix before running):** no undeclared cycle; a second run changes nothing except declared metadata.
- **Failure signature:** row counts that grow on every run; a file read and written by the same step; a model's scores feeding the labels or priors it is later judged against (a self-fulfilling loop).
- **Source:** Sandve et al. (2013); Landau (2021).

### 2.3 Freshness and staleness gates
- **Tests:** whether each artifact is newer than its inputs and within its allowed age.
- **Assumptions of the test itself:** declared dependencies are complete. Modification times change on copy, checkout and cloud sync, so a content-hash manifest is the stronger test.
- **Run it:** for each artifact list its upstreams and a maximum age; flag artifacts older than any upstream (Make logic) and inputs past expiry; compare a stored input-hash manifest with current inputs. R pipelines under `targets` report outdated targets from content hashes (`targets::tar_outdated()`). Stale inputs follow the gate rule of 2.9: spend, legal and safety gates fail closed; an evidence gate may fail open only if the direction is documented and every fallback is counted and printed; no T1 output fails silently.
  ```python
  import os
  deps = {"clean.csv": ["raw.csv"], "scores.json": ["clean.csv"]}           # artifact -> declared upstreams
  mt = {f: os.path.getmtime(f) for f in set(deps) | {u for ups in deps.values() for u in ups}}
  print([t for t, ups in deps.items() if any(mt[u] > mt[t] for u in ups)])   # older than an upstream: stale
  ```
- **Pass criterion (fix before running):** no artifact older than an upstream; every T1 input within its maximum age; the hash manifest matches.
- **Failure signature:** a driver file months old feeding every downstream model; a refresh that updated the raw pull but not the derived tables; a modification-time check that passes after a copy.
- **Source:** Landau (2021); timeliness and completeness expectations for risk data are in `regulatory.md` (BCBS 239).

### 2.4 Point-in-time data vintages
- **Tests:** whether every backtest and historical figure uses data as it was known on the date it claims.
- **Assumptions of the test itself:** each record carries an availability time (filing, publication or retrieval), not only an event time.
- **Run it:** rebuild inputs as of each forecast origin: real-time macro series from vintage archives (ALFRED/FRED `realtime_start` and `realtime_end`); filings under the amendment rule in force then; filing lags respected as embargoes. Screen features available only after the prediction time: `python scripts/leakage_audit.py --train train.csv --test test.csv --time origin_date --available-at available_at --embargo 90D`. Record retrieval time, source and SHA-256 for every pull (`citation.md`).
- **Pass criterion (fix before running):** zero rows or features available after the prediction time; one vintage per analysis, stated beside every number.
- **Failure signature:** backtests on latest-revised totals; amended filings silently replacing originals in history; one "latest" pull used for every past origin.
- **Source:** Croushore & Stark (2001); Kapoor & Narayanan (2023); vintage rules for money and macro data: `finance.md`, `citation.md`.

### 2.5 Dependency drift and lockfiles
- **Tests:** whether the environment that produced a result can be rebuilt, and whether an upgrade changed results.
- **Assumptions of the test itself:** a lockfile pins the full transitive set; interpreter, OS, system libraries and compilers are recorded separately, because lockfiles do not cover them.
- **Run it:** R: `renv.lock` present and `renv::status()` reporting no drift. Python: a committed `uv.lock` or `pylock.toml` (PEP 751, status Final as of 2026-09-30; re-verify tool support before relying) and an environment built from it (`uv sync --frozen`). Record `sessionInfo()` or `importlib.metadata` versions in each run's provenance; this skill's scripts store package versions in `report.json`. When results moved between versions, rerun the old lock on the new code (owner-gated) to separate code effects from dependency effects.
- **Pass criterion (fix before running):** lockfile present, in sync and cited in each result's provenance; every behavior-changing upgrade re-validated.
- **Failure signature:** no lockfile; the lock names one version while the environment runs another; numbers changed with no code change.
- **Source:** renv documentation; PEP 751; Sandve et al. (2013); Vilhuber (2020).

### 2.6 Clean-checkout reproducibility
- **Tests:** whether the commit cited for a result actually produces it, independent of anyone's working tree.
- **Assumptions of the test itself:** inputs outside version control are listed and supplied from a pinned location. A green suite in a dirty tree proves only that the dirty tree works.
- **Run it:** read-only on the repository: `git --no-optional-locks status --porcelain` (untracked or modified files the code imports? the flag stops git refreshing its index), then export the commit's bytes with line-ending conversion off: `git -c core.autocrlf=false archive --format=zip -o <scratch>/head.zip HEAD` (a large repository can yield gigabytes; append `-- <paths>` to export only what the computation needs). Unpack outside the repository, supply only the documented inputs, run the test suite and the headline computation there (owner-gated), and compare output hashes with the reference run (2.1). In a DataLad dataset, `datalad rerun --report` lists the recorded commands; rerunning onto a separate branch and diffing the results is a reproduction test. A replication package should carry a README with a program-to-output map (Social Science Data Editors template; `citation.md`).
- **Pass criterion (fix before running):** the suite passes and the headline numbers match from the clean export with documented inputs only.
- **Failure signature:** imports of untracked modules; paths that resolve back into the developer's tree; a test that passes only while a stale cached artifact is present; hashes that differ because of line-ending conversion.
- **Source:** Trisovic et al. (2022); Pimentel et al. (2019); Lamb & Zacchiroli (2022); Vilhuber (2020); Halchenko et al. (2021).

### 2.7 Canonical recipe `parity_check`: one model, several implementations
- **Tests:** whether every copy of the same mathematics agrees: back-end engine, front-end mirror, report or desk port, spreadsheet. This is the recipe's one home; the front-end divergences to probe (rounding and tie rules, quantile type, null versus 0, dates, stale constants) are listed in `data-visualization.md` §2.9.
- **Assumptions of the test itself:** both copies run on one golden fixture that exercises the edge cases (zeros, caps, ties, missing values, negatives, gates, tier boundaries). Tolerances are fixed before comparing and never below the precision the inputs carry: when a copy reads rounded exports, jitter each rounded input within its rounding, rerun the reference, and take that spread as the floor for `atol` (a tighter bar cannot be met).
- **Run it:** inventory implementations by searching every language for the formula's distinctive constants and function names; trace each constant to one definition (literals copied into a mirror cannot see configuration overrides); run both copies on the fixture; compare.
  ```python
  import numpy as np, pandas as pd
  def parity_check(ref_csv, other_csv, key, fields, rtol=1e-9, atol=0.0):
      """Reference implementation vs another copy on one golden fixture: coverage first, then every
      field; a null must meet a null (a null read as 0 counts as a mismatch)."""
      a, b = pd.read_csv(ref_csv), pd.read_csv(other_csv)
      m = a.merge(b, on=key, how="outer", suffixes=("_ref", "_other"), indicator=True, validate="one_to_one")
      out = {"coverage": m["_merge"].value_counts().to_dict(), "fields": {}}
      both = m[m["_merge"] == "both"]
      for f in fields:
          x, y = both[f + "_ref"], both[f + "_other"]
          bad = pd.Series(~np.isclose(x, y, rtol=rtol, atol=atol, equal_nan=True), index=both.index)
          d = (x - y).abs()[bad]                                  # numeric gaps among the mismatches
          worst = both.loc[d.idxmax(), key] if d.notna().any() else (both.loc[bad.idxmax(), key] if bad.any() else None)
          out["fields"][f] = {"mismatches": int(bad.sum()), "null_vs_value": int((x.isna() != y.isna()).sum()), "worst": worst}
      return out
  print(parity_check("engine_out.csv", "mirror_out.csv", "case_id", ["value"], atol=1e-6))
  ```
  For stochastic outputs, compare under common random numbers and test equivalence at a pre-stated margin, never "no significant difference" (`engineering-simulation.md` §2.3). Prove the parity check itself can fail (`engineering-simulation.md` §2.14).
- **Pass criterion (fix before running):** coverage complete (no left-only or right-only rows); zero mismatches and zero null-versus-value rows at the stated tolerance (for example 1e-9 relative for deterministic code, or the propagated input precision); one definition per constant; parity re-run after every change to any copy.
- **Failure signature:** a parity check run once and cited for months; a tolerance tighter than the exported precision allows; a port applying different gates, imputation or rounding; a front end reading null as 0; a surface label naming a unit the code does not compute.
- **Source:** Barr et al. (2015); Chen et al. (2019); adapted from K-Dense `analytical-method-validation` (equivalence at a stated margin).

### 2.8 Audit-harness integrity
- **Tests:** whether the audit suite can detect what it claims to guard.
- **Assumptions of the test itself:** each check's body and the artifact it reads are available to read.
- **Run it:** for each check record the artifact read (raw or post-processed), the rule, the threshold history (`git log -S "<literal>" -- <file>` lists every commit that changed a literal), and the behavior when the input is missing: SKIP must never count as PASS. Distrust gates that count checks ("at least N passed") instead of inspecting content, and fixtures regenerated by the code under test. Prove each check can fail: `python scripts/mutation_check.py --input artifact.json --auto --cmd python check_x.py '{input}'`, declaring by-design survivors with `--expect-survive` (a row-wise identity check cannot see whole rows dropped or duplicated: `--expect-survive drop_rows,dup_rows`). It executes the command: never aim it at code whose import executes it; run a scratch copy of the check's predicate that reads `{input}`. A KILLED it prints is a candidate until a second independent reader confirms it. Mechanics: `engineering-simulation.md` §2.14.
- **Pass criterion (fix before running):** every check kills its targeted mutants; missing inputs give SKIP or FAIL, never PASS; no threshold relaxed without a recorded reason.
- **Failure signature:** a monotonicity check reading a clamped series; a tripwire relaxed several times after failures; a suite that passes with its data directory empty.
- **Source:** Jia & Harman (2011); Barr et al. (2015).

### 2.9 Silent fallbacks and neutral defaults
- **Tests:** whether missing or unmatched inputs fail visibly, and whether each gate fails in the right direction.
- **Assumptions of the test itself:** the census covers every language in the pipeline (Python, R, SQL, front-end code).
- **Run it:** census fallback sites read-only (the script below reads files and imports nothing from them), then classify each site: which input, which default, logged or silent, which gate type.
  ```python
  import pathlib, re
  PATTERNS = {".py": r"\bexcept\b[^:\n]*:\s*(pass|continue|return)\b|\.get\([^)]*,\s*(0|1|1\.0|None)\)|fillna\(|os\.path\.exists",
              ".r": r"tryCatch|%\|\|%|ifelse\(is\.na"}                   # extend for SQL and front-end code
  for f in sorted(pathlib.Path("src").rglob("*")):                         # root of the audited code
      pat = PATTERNS.get(f.suffix.lower())
      if pat and f.is_file():
          text = f.read_text(encoding="utf-8", errors="replace")
          for m in re.finditer(pat, text):                                # a handler body may sit on the next line
              n = text.count("\n", 0, m.start()) + 1
              print(f"{f}:{n}: {text.splitlines()[n - 1].strip()}")
  ```
  One rule for every gate: **spend, legal and safety gates fail closed. An evidence gate may fail open only if the direction is documented and every fallback is counted and printed; no T1 output fails silently.** Report beside each result the share of units that ran on a default or an unmatched join. Drill (owner-gated): in a scratch copy, remove one input and rerun; a T1 output that changes without a warning or a failure is a finding.
- **Pass criterion (fix before running):** every spend, legal and safety gate fails closed; every evidence gate that fails open has its direction documented and its fallbacks counted and printed; no T1 output changes silently; the default share is reported with the result.
- **Failure signature:** a multiplier that silently turns neutral when its artifact is missing; an ID mismatch producing zeros that read as "no money"; outputs that look normal with an input absent.
- **Source:** adapted from K-Dense `database-lookup` (references/retrieval-contract.md: reconcile counts, stop and report mismatches) and `waypoint-bio` (silent drops); coverage tests in `multi-omics-transfer.md` §2.9.

### 2.10 Provenance and lineage records
- **Tests:** whether each reported number traces to its inputs, code, parameters and seed, and can be recomputed.
- **Assumptions of the test itself:** hashes were taken on bytes as fetched or as committed, not on a normalized copy; a stored hash is a dated observation, re-checked at the point of use.
- **Run it:** require a PROV-style record per artifact: `used` (inputs with source, retrieval time, vintage, SHA-256), `wasGeneratedBy` (script, commit, parameters, seed, start and end times), `wasDerivedFrom`, `wasAttributedTo`. DataLad `run` records the command, inputs and outputs with the change itself (a run that changes nothing records no commit, so a missing record is not proof of failure); R `targets` reruns only outdated steps. Trace three to five headline numbers to their records, re-hash the inputs, and recompute each by an independent path.
  ```python
  import hashlib, json, pathlib
  def sha(p): return hashlib.sha256(pathlib.Path(p).read_bytes()).hexdigest()
  rec = json.loads(pathlib.Path("lineage.json").read_text(encoding="utf-8"))
  for e in [rec["artifact"], *rec["used"]]:              # entries like {"path": ..., "sha256": ...}
      print(e["path"], "OK" if sha(e["path"]) == e["sha256"] else "CHANGED since the record")
  ```
- **Pass criterion (fix before running):** every T1 number has a record; re-hashes match or the change is explained; the independent recomputation agrees within tolerance.
- **Failure signature:** a number that exists only in a log, a chat or a slide; hashes of line-ending-normalized copies; a lineage record edited by hand.
- **Source:** W3C (2013) PROV; NIST (2015) FIPS 180-4; Halchenko et al. (2021); Landau (2021); Wilkinson et al. (2016); claim ledgers in `citation.md`.

### 2.11 Observability: every process emits
- **Tests:** whether each long-running or scheduled process leaves a machine-readable trail of progress, completion or failure.
- **Assumptions of the test itself:** the stream is append-only, one file or line per event, written atomically (temporary file, then rename).
- **Run it:** find the events for each process's last run: started, per-stage progress with current and total counts, then completed or failed, with duration and exit code, all tied to one run id. A shared directory of JSON event files (a "Glass Box") is one workable design. This skill's scripts write started, stage, completed and failed events there when `~/.claude/glassbox/events` exists or `GLASSBOX_EVENTS_DIR` is set. These events are the one write the scripts make outside `--out`: pass `--no-glassbox` (or set `QME_GLASSBOX=0`) when a caller restricts writes to one folder. Long analyses written during an audit should emit too.
  ```python
  import json, pathlib
  events_dir = pathlib.Path.home() / ".claude" / "glassbox" / "events"; run_id = "qme-mc_error-..."
  events, unreadable = [], 0
  for p in events_dir.glob("evt-*.json"):
      try: events.append(json.loads(p.read_text(encoding="utf-8-sig")))   # tolerate a byte-order mark
      except (ValueError, OSError): unreadable += 1                        # count bad events; never hide them
  run = sorted((e for e in events if e.get("run_id") == run_id), key=lambda e: e.get("timestamp_utc", ""))
  print(unreadable, [(e.get("kind"), e.get("status"), e.get("stage")) for e in run])   # started ... completed|failed
  ```
- **Pass criterion (fix before running):** the last run of every T1 process shows started and completed (or failed) events plus per-stage progress, under a run id that matches its outputs' provenance; the reader reports its count of unreadable events.
- **Failure signature:** a process with no events; progress printed only to a console nobody watches; logs overwritten each run; completion inferred from silence; a reader that crashes on one malformed or byte-order-marked event file and so hides every other event (mixed writers, such as shell tools that add a BOM, make this common).
- **Source:** Sandve et al. (2013); this skill's event emitter (`scripts/_common.py`).

### 2.12 Verify, do not infer, completion
- **Tests:** whether a background or scheduled job actually wrote correct outputs, whatever it printed.
- **Assumptions of the test itself:** the artifacts the job must write and its start time are known.
- **Run it:** for each expected artifact check existence, a modification time after the job start, a changed (or expected) hash and plausible content (row counts, totals within range), and look for the job's completion event (2.11). Negative control: point the same check at a job known to have failed and confirm it reports failure. Check once at the expected finish with a bounded wait; never poll in a loop that burns resources.
  ```python
  import hashlib, pathlib
  def landed(path, job_started_epoch, previous_sha=None):
      """Did a background or scheduled job actually write its artifact?"""
      p = pathlib.Path(path)
      if not p.exists(): return "MISSING"
      if p.stat().st_mtime < job_started_epoch: return "STALE: older than the job start"
      h = hashlib.sha256(p.read_bytes()).hexdigest()
      return "UNCHANGED: same bytes as before" if h == previous_sha else "LANDED"
  ```
- **Pass criterion (fix before running):** every expected artifact is LANDED with plausible content, and the negative control is flagged.
- **Failure signature:** "COMPLETE" printed after a skipped step; exit code 0 with nothing written; a job killed by a restart and reported as done; success inferred from elapsed time.
- **Source:** Sandve et al. (2013).

### 2.13 Held-out gate for tuning loops
- **Tests:** whether a tuned dial, threshold or configuration improves on data the search never touched.
- **Assumptions of the test itself:** the test evaluator is separate (another period, split or seed set) and hidden from the search.
- **Run it:** a development evaluator steers the search freely; a test evaluator admits a change only when it improves there and is never used as a search oracle. Count every configuration tried, report the development-test gap, and correct for the search when many were tried (White's reality check and its successors, the probability of backtest overfitting, the deflated Sharpe ratio: `finance.md`).
- **Pass criterion (fix before running):** test evaluator untouched during the search; the improvement holds on test; the number of looks reported.
- **Failure signature:** one dataset used both to tune and to accept; a threshold moved after seeing the test result; many variants tried, one reported.
- **Source:** White (2000); Bailey et al. (2014); adapted from K-Dense `arbor` (development guides, test admits).

### 2.14 Concurrency, partial writes and stale locks
- **Tests:** whether overlapping jobs can corrupt or half-read artifacts.
- **Assumptions of the test itself:** every writer of each artifact (from the 2.2 census) and each job's schedule are known.
- **Run it:** confirm writers replace files atomically (temporary file, then rename) and readers check completeness (row count, footer or manifest hash); confirm no artifact has two writers that can run at once; confirm lock files name their owner and are cleared or detected as stale after a crash; confirm collectors and the main chain cannot overlap.
- **Pass criterion (fix before running):** atomic writes, one writer per artifact at a time, stale-lock detection.
- **Failure signature:** a truncated file read mid-write; a hung process holding a lock for days; interleaved outputs from overlapping runs.
- **Source:** Luo et al. (2014).

- **AUT-16** Confirm each audit check reads the raw artifact, not a display or post-processed copy. `COMPUTATIONAL` · 2.8
- **AUT-17** Prove each check can fail on a scratch copy of its predicate (never code whose import executes it), declaring by-design survivors; SKIP never counts as PASS. `COMPUTATIONAL` · 2.8, `scripts/mutation_check.py`
- **AUT-18** Review the history of every tripwire threshold; each relaxation needs a recorded reason. `DECISION` · 2.8
- **AUT-19** Census fallbacks and neutral defaults and classify each by gate type. `DATA` · 2.9
- **AUT-20** Report beside each result the share of units computed from defaults or unmatched joins. `PRESENTATION` · 2.9
- **AUT-21** Keep a PROV-style lineage record per artifact; recompute headline numbers by an independent path. `DATA` · 2.10
- **AUT-22** Require started, progress and completed or failed events under one run id for every long or scheduled process. `COMPUTATIONAL` · 2.11
- **AUT-23** Verify background and scheduled jobs landed their outputs; include a known-failed job as a negative control. `COMPUTATIONAL` · 2.12
- **AUT-24** Keep a held-out test evaluator for every tuning loop and report the number of configurations tried. `STATISTICAL` · 2.13
- **AUT-25** Check atomic writes, single writers and stale-lock detection for every artifact a scheduled job touches. `COMPUTATIONAL` · 2.14

## 4. Pitfalls and anti-patterns

- A green test suite in a dirty working tree cited as proof that a commit works.
- "The job printed COMPLETE" accepted without checking that each artifact is new and plausible.
- Polling a running job in a tight loop instead of checking once with a bounded wait.
- Parity verified once and cited indefinitely while every copy keeps changing.
- Constants copied as literals into a front-end mirror, so configuration overrides reach only the back end.
- Neutral fallbacks that keep outputs looking normal when an input is missing.
- Unmatched joins filled with zero, so a resolver failure reads as a true zero.
- Hashes taken on normalized copies, or treated as permanent truths instead of dated observations.
- Model outputs folded back into the next cycle's inputs or labels without anyone deciding to.
- Threshold ratchets: each failed audit answered by relaxing the tripwire.
- Freshness judged by modification times on files that sync or checkout rewrites.
- Numbers that exist only in session logs or slides, with no lineage record.
