## 1. Executive summary

The current influence network is CU-scoped **at the collection layer, not in the build code**. The base cosponsor graph is assembled by an external R scraper from 17 credit-union-topic congress.gov search templates; the press and social layers are CU-scoped by their corpora (a CU press CSV and a CU-boolean Quorum export). There is no "bill guard" switch to flip off: **building the holistic layer is a data-sourcing project plus a parallel builder, not a filter removal.**

The good news is that the *injection seam* exists: the cascade kernel already accepts an injected adjacency (`build_P(adj=…)`), every engine binds the graph at one line, and the repo has a shipped precedent for running the full engine stack against an alternate network in a sealed root. The surrounding plumbing — dual-loader selection dial, config-keyed caches, glob isolation, bundle wiring, schema extension — is real, enumerated work (§4–5), not something the repo does today. The riskiest parts are (a) a naming/selection trap — the loader silently picks the newest augmented workbook by mtime, so a second network file must live under a name the existing glob can never see, behind an explicit selection dial; (b) weight scale — the kernel's "weight 6 ≈ 50% activation" constant sits against CU-universe edge weights, and an all-bills universe will inflate raw weights toward saturation unless the holistic builder normalizes deliberately; and (c) honest labeling — some interaction sources cannot be made fully holistic without new collection, and the artifact must say so per-layer.

This guide gives the full current-state anatomy (§2), the guard inventory being stripped (§3), the holistic design (§4), a phased implementation plan (§5), the risk register (§6), and a numbered decision menu for Paul (§7). Nothing moves until the menu is ruled on.

## 2. What exists today (baseline anatomy)

### 2.1 Two-stage network production

**Stage A — base cosponsor graph (external producer).** `congress_member_scraper.R` (in-repo only as the audit snapshot `audits/legfix5/draft_systems_scraper_snapshot_20260726/`, dated 2026-07-26; the live copy in Paul's Draft Systems folder has **not** been diffed against the snapshot — everything below is snapshot-vintage, and Phase 2's reconciliation doubles as the drift check) walks bills from 17 CU-topic congress.gov advanced-search templates over congresses 117–119 and writes `congress_cosponsor_network_<ts>.xlsx` with a directed Edges sheet: `From, To, Weight, NBills, NOriginal, NRegular, From_label, To_label`. Edge weight per bill-tie:

```
w = role_weight × SUCCESS × DECAY × sizenorm(C)      [net: ÷ sqrt(C)]
    role_weight: 1.0 original cosponsor / 0.5 regular cosponsor   (scraper :1773-1774, :1932)
    SUCCESS_MULT = 3.0 for a bill that passed its origin chamber   (:1780)
    DECAY = 0.8^(119 − congress)                                   (:108-115)
    sizenorm(C) = 1/sqrt(C), C = bill's cosponsor count — a
    MULTIPLIED discount (f_bill = f_succ·f_decay·sizenorm, :1927);
    big multi-cosponsor bills are penalized, never boosted          (:1788)
```

summed across bills per member pair (`:1949-1951`). **Read the formula carefully:** every edge runs **sponsor → cosponsor** (`:1917`) — the sponsor is the source of every tie, so "sponsor" is not a weight class. `role_weight` prices the *cosponsor's* commitment: original cosponsors tie at 1.0, and **regular cosponsors are in today's CU graph too, at half weight** — a fact the say-do gate (which refuses plain cosponsorship as evidence) can make easy to misremember. How regular-cosponsor ties are priced in the holistic layer was ruled mid-run — see **D1** (included, at 0.2).

**Stage B — the multiplex augmenter (in-repo, weekly refresh).** `fec/network/build_multilayer_network.py` folds three interaction layers onto the cosponsor graph and writes `congress_cosponsor_network_AUG<date>.xlsx` — a 3-column Edges sheet (`source_bioguide, target_bioguide, weight`) plus a Provenance sheet carrying each edge's layer tag. Layer policy (`:9-19` for layers 1–3; the social layer's policy and dials live at `:77-83`):

1. **Cosponsor** edges copied verbatim, mean-symmetrized.
2. **Press engagement** (`press_engagement.json`, Fink-normalized probabilities) — added for untied pairs only, converted by the kernel-inverse `w = 6p/(1−p)`, capped `ENG_CAP=2.0`.
3. **HCoI topic-affinity** — added *only* for edges touching a cosponsor-isolated member (the D4 surgical fix), weight ≤ 0.12.
4. **Social** (X/Quorum reposts + mentions, plus Bluesky *mentions only* — Bluesky reposts are collected as posts but never become interaction edges) — new edges via the same kernel-inverse (cap `SOC_CAP=2.0`); already-tied pairs get reinforcement `w ×= 1 + SOC_REINF·min(1, p/0.10)` (default cap +30%).

**Two interaction sources exist but never reach the engine graph:** co-appearance (joint interview episodes, `data/network/co_appearance.json`) and signed member references (`signed_coalitions.json`) are dashboard/diagnostic layers only (`build_dashboard_bundle.py:179-194`).

### 2.2 Loading and consumption

`moneyball_core.load_network()` (`:238-255`) is the single adjacency authority: glob `congress_cosponsor_network_*.xlsx`, **prefer any filename containing `AUG`, take newest mtime** (`select_network_file`, `:232-237`), filter both endpoints to the 533-member `congestion.json` roster, mean-symmetrize, memoize in the process cache `_c['adj']`. A directed variant (`load_network_directed`, `:267-292`) reads the newest **non-AUG** file — the only vintage that still carries direction. The cascade kernel `build_P(adj=None, physics=cpf_diffusion, edge_mult=True)` (`:305-312`) converts weights to activation probabilities `p = w·cpf·σ_v/(w·cpf·σ_v + 6)`.

Thirteen engine call sites consume `load_network()`/`build_P` (budget_frontier, per_topic_coalition, per_topic_flip, flip_model, lt_priming, scenario, salience_shock, cosponsor_route, kb_benchmark, method_audit, assemble_viz, sna_layout, run_tests); a fourteenth — the member desk — consumes `load_network_directed()`, a *separate* loader with its own glob and cache. The JS surfaces get the graph serialized by `build_dashboard_bundle.py` (`ADJ` at `:235`) into `dashboard_data.json`, where the dashboard template re-derives the same kernel (`make_dashboard_html_00.tpl:414-417`).

### 2.3 The pathfinder variants (what "feeds into" means)

- **Python:** `fec/engine/cosponsor_route.py` — RELINK + MOPBD*-style multi-objective recruitment routing: greedy routes at risk-aversion λ ∈ {0, 0.5, 1, 2, 4}, Pareto front over (money, cosponsors gained, cascade-failure risk), optional exact-MC reach. Binds the graph at one line (`:16 adj=MBC.load_network()`); everything below is graph-agnostic. Operational facts that shape Phase 4: it is a module-level script (no `main()`, no importable function), it **prints only — no artifact is written** — and it sits outside the `run_pipeline.py` chain.
- **Dashboard JS** (`make_dashboard_html_00.tpl`, hand-maintained mirror): `tracePath`/`buildPath` (max-product Dijkstra chain), `bestSponsors`, `multiTarget` (shared trees), `budgetRecruit` (GCOMB cost-bounded max-coverage), `closedCascadeRoute` (RELINK closed-network edge activation), the cascade sub-modes, plus PageRank/Katz structural priors. All read one probability matrix `PE` rebuilt from the serialized `adj`.
- **Member-desk JS recommender** (`make_member_desk_00.tpl`): coverage/marginal-gain/basis-scores machinery with a directed-edge capability flag (`HAS_DIR`) — the shipped precedent for a *second* edge array traveling in the same bundle.
- **D*-Lite** is a cited design principle (scenario.py:13), not an implementation; there is no D*/D*-Lite replanner in the repo.

All pathfinder variants therefore hang off exactly two artifacts: the engine adjacency (via `load_network`) and the serialized bundle graph. Feed those two points and every variant is reachable.

## 4. The holistic configuration — design

### 4.1 Identity: a second configuration, not a replacement

Per the pinned run invariants: the CU-scoped network stays untouched and remains the default everywhere (INV-2); the holistic layer is additive. Concretely that means a **new artifact family, a new selection dial, and untouched defaults**:

- **Artifact naming — must not match the production glob, and must encode vintage.** The engine glob is `congress_cosponsor_network_*.xlsx`; anything matching it participates in mtime selection, and `load_network_directed` picks the newest **non-AUG** match — so even a "clearly different" name like `congress_cosponsor_network_HOLISTIC_*.xlsx` would silently hijack the directed loader. The holistic family fails that glob entirely **and names its two vintages explicitly**: `holistic_network_BASE_<date>.xlsx` (the directed base, extended schema per §4.5) and `holistic_network_AUG_<date>.xlsx` (the multiplexed engine artifact, Edges + Provenance). Intra-family selection mirrors the CU semantics *categorically*: the engine loader picks the newest `AUG` vintage if any exists (a newer BASE never displaces an AUG — same rule as CU today), the directed loader picks the newest `BASE`; zero files of the needed vintage under `NET_CONFIG=holistic` raises, never falls back to CU. The legislation lane's `PRODUCTION_WORKBOOK_RE` prohibition is the shipped precedent for treating name collision as a contract error.
- **Selection dial.** `NET_CONFIG` env dial, default `cu` (absent = today's behavior byte-for-byte). `NET_CONFIG=holistic` makes `load_network()` resolve the holistic family (newest by mtime *within that family*, fail-closed if zero files). **The dial must gate BOTH loaders**: `load_network_directed()` has its own glob and cache and a live consumer (the member desk's directed recommender) — left unkeyed it would silently bind the CU directed base while every other engine binds the holistic graph, a mixed-config run with no error. Holistic-directed resolves to the holistic *base* file (the only direction-preserving vintage; any AUG-analog destroys direction via min/max re-keying exactly as today's does). The memo cache must key on the config across all its entries (`adj`, `dadj`, `netfile`, `dnetfile`) — the current single `'adj'` key would otherwise serve one config's graph to the other inside a process.
- **Fail-closed ambiguity, full selection-surface inventory.** Mirror the shadow-lane rule: if selection inside a family is ambiguous under the rules above, raise; never guess. And be honest that the loaders are not the whole selection surface — **four** sites choose a graph and every one must be config-aware or config-immune: (1) `load_network()`, (2) `load_network_directed()`, (3) the weekly-refresh augmenter's own base-pick glob (§6.1 — it must *never* see holistic files), and (4) the bundle builder's file selection for `dashboard_data.json` (§4.6). Audit/test globs (`run_tests.py`, `audit_full` freshness checks) are a fifth, read-only surface to sweep during Phase 3.
- The sealed-root alternative (`MONEYBALL_ROOT` pointing at a run directory, as `run_legislation_network_dependents.py` does) remains available for one-off audits, but a dial is the right shape for a *standing* second configuration that pathfinders switch on per-run. **Decision D3.**

**D1 — the "regular co-sponsorship" treatment: RULED (Paul, 2026-08-17, mid-run).** The original directive read "taking every single interaction, besides regular co-sponsorship," which admitted three readings (exclude regular; include everything; exclude all cosponsorship). The ambiguity was resolved live during this run's drafting exchange: after seeing that the current CU graph prices regular cosponsors at 0.5, **Paul ruled that the holistic layer includes regular co-sponsorship at role weight 0.2** — kept as a tie, priced well below an original cosponsorship (1.0), and below its CU-graph weight (0.5). Rationale consistent with repo vocabulary: original cosponsorship is the costly signal (say-do gate Path A counts it; plain cosponsorship does not), so on an all-bills universe the cheap, high-volume tie is retained but strongly down-weighted rather than dropped.

The builder still makes this a dial, not a constant: `HOLISTIC_REGULAR_W` (default **0.2** per the ruling) and `HOLISTIC_ORIGINAL_W` (default 1.0). Because the base schema carries per-role weight subtotals (§4.5), any future re-ruling is a base-side recompute plus an augmenter re-run, **not a re-collection**. The ruling is recorded in the run ledger (`decision-resolved: d1-regular-cosponsor-ruling`) with the pinned invariants revised accordingly. Note the scope boundary: this ruling prices the *holistic* layer only — the CU graph's 0.5 lives in the external scraper and is untouched (INV-2). **And a warning the coefficient does not carry on its own:** 0.2 is a *per-tie* price, not a dyad-mass cap. On an all-bills universe frequent collaborators regular-cosponsor constantly and original-cosponsor rarely, and `SUCCESS_MULT=3.0` plus recency amplify the cheap pile — e.g. fifty modest regular ties (0.2 × 1.0 × 0.8 / √25 ≈ 0.032 each) sum to ≈1.6 against three strong originals at ≈0.48. The `1/√C` norm discounts mega-bill pile-ons, not small exclusive regulars. Whether regular mass dominates original mass per dyad is a **Phase-5 measured quantity** (per-dyad role-mass shares), reported to Paul before anyone reads the holistic graph as a costly-signal network.

**Partial holism is labeled, never hidden.** Press/HCoI stay CU-scoped until their corpora are re-collected (G2/G3 are external). The artifact's manifest and the surfaces must carry a per-layer `scope` field (`all-bills` / `cu-corpus`) so nobody reads a mixed graph as fully holistic — **and the scope table must cover kernel multipliers, not just adjacency layers**: the default cross-party physics `cpf_diffusion` multiplies every cross-party edge by a factor of `bpf`, which is read from `bipartisan.json` — *defined on CU cosponsorship* — so even a fully holistic adjacency runs with a CU-scoped cross-party prior (in Python and in the serialized-BPF JS mirror alike). Record `bpf: cu-scoped` in the manifest; a holistic bipartisan fraction is a possible future input, gated like every other rank-adjacent surface (§4.6). Accepting labeled partial holism for v1 — rather than blocking on an all-topic press re-collection campaign — is itself a ruling: **decision D9**. This follows the honest-gap rule (the 8-state QCEW precedent: never relabel a gap).

### 4.3 Time frame

"Over a designated time frame" becomes two dials, defaults matching the current graph. Be precise about what that buys: **shared dials, not comparable numbers.** Different universes (17 templates vs all bills) and different regular weights (0.5 vs 0.2) mean raw cross-config weights, activation probabilities, and cascade-reach figures are *never* directly comparable — Phase 4 side-by-sides compare route shape, rankings, and qualitative structure only, and any report that quotes a raw holistic-vs-CU `p` or reach delta is a defect. The matched defaults exist so the *time semantics* line up:

- `HOLISTIC_CONGRESSES` — default `117,118,119` (the current universe).
- `HOLISTIC_DECAY` — default `0.8` per congress of age (the scraper's table: 119→1.0, 118→0.8, 117→0.64). The legislation lane uses a materially steeper table (`{116:0.16, 117:0.33, 118:0.66, 119:1.0}` — roughly halving per congress); the two are **not** interchangeable. **Pick the scraper table** for weight comparability with the CU graph and record the fork. Optional finer windowing (date-range on bill action dates / social timestamps) is a v2 item; congress-level windows are what every current consumer understands. **Decision D4.**
- The 120th-Congress rollover campaign owns the roster-swap consequences; the holistic builder must read the congress set from its dial, not hardcode 119, so the rollover is a one-line bump here too.

### 4.4 Sourcing the holistic base graph (the biggest work item)

The CU base graph comes from an out-of-repo R scraper against congress.gov search pages. For an *all-bills* universe there are four candidate sources — **verify coverage in this order before building anything** (cheapest, most local first):

1. **The local BILLSTATUS archive** (`%LOCALAPPDATA%\Melange\lda_rebuild\raw`) — already consumed by `cosponsor_selectivity.py` for denominators across congresses 117–119. BILLSTATUS XML carries sponsor, every cosponsor, cosponsorship *date*, and the `isOriginalCosponsor` flag — exactly the holistic schema. **Open question: is the archive complete for all bill types across 117–119, or only the slices the LDA rebuild needed?** Note that its one existing consumer proves nothing about completeness: `cosponsor_selectivity`'s own universe is CU-category-scoped (G7), so the archive has never been exercised as an all-bills source. A read-only coverage census (bills present per congress/type vs. official counts) is Phase 1 step 1.

Whatever the source, four **build-contract definitions must be written down before Codex builds** (they are D6 sub-questions, and getting them wrong silently corrupts half the universe): (a) the **bill-type set** — which of HR/S/HJRes/SJRes/HConRes/SConRes/HRes/SRes enter, given that simple and concurrent resolutions never "pass a chamber" in the SUCCESS sense; (b) the **SUCCESS parse** — which BILLSTATUS action codes count as "passed its origin chamber" per type (the R scraper's regex is the reference, not the spec); (c) the **C definition** — whether the size-norm's cosponsor count is the full bill's or the roster-filtered subset; (d) the **departed-sponsor policy** — the star topology means a bill whose *sponsor* is off the 533-member roster contributes **zero ties, even among its sitting cosponsors**; over 117–118 that is a material slice of the universe. Options: accept the drop (parity with the CU graph's identical behavior — comparable, not holistic) or synthesize co-cosponsor ties for those bills (which is the D11 clique question arriving early). The 119th also keeps accruing regular cosponsors until 2027-01-03, so a one-shot pull goes stale — refresh cadence and its owner ride D7.
2. **The BICAM snapshot** (`C:\melange-data\bicam_snapshot`, acquired 2026-08-17, sha256-verified) — the arrival audit's run 3 (2026-08-17, fixed defaults, native strata superseding the earlier run-2 sidecar arithmetic) showed pre-119th bill joins 322/322 (100%) and identity-perfect cosponsor agreement (symmetric difference 0 across 304 acts / 1,288 cosponsor entries), but the drop is mixed-vintage: bills effectively end at a 131-bill early-January 119th sliver (data-last-updated 2025-01-25). **Strong for 117–118; unusable alone for 119.** Calibration caution: those audits sampled the CU act universe (304 acts) — treat them as evidence of join *mechanics*, not as an all-bills quality prior over ~48k bills.

4. **A holistic re-run of the R scraper** — possible but worst-fit: congress.gov search pagination over a universe on the order of 48,000 bills and resolutions introduced across congresses 117–119 combined (exact per-congress denominators come from the Phase-1 census against official congress.gov counts) is exactly what bulk data exists to avoid. Keep as fallback only.

Likely outcome: a **new in-repo Python producer** (`fec/network/build_holistic_base.py`) reading BILLSTATUS-format XML (from source 1 and/or 3, cross-checked against 2), replicating the Stage-A weight formula (§2.1) with the D1 role weights, writing `holistic_network_<date>.xlsx` in the extended schema of §4.5. Bringing the base-graph build *into* the repo/audit perimeter for the first time is a side benefit worth naming. **Decision D6.**

### 4.5 Schema: carry the evidence through

The current AUG pipeline throws away `NBills`/`NOriginal`/`NRegular` (3-column read at `build_multilayer_network.py:36` / `moneyball_core.py:247`), which is why D1 would otherwise require re-collection to revisit. But counts alone are **not enough to re-weight**: the stored `Weight` is a sum of `role_w × (SUCCESS·DECAY/√C)` terms whose per-bill factors vary, so `(Weight, NOriginal, NRegular)` cannot be decomposed into role components after the fact. The holistic **BASE** file therefore extends the schema with **per-role weight subtotals with the role weights factored out**: `WOriginal = Σ f_bill` over original-cosponsor ties and `WRegular = Σ f_bill` over regular ties, per *directed* edge (both directions preserved — symmetrization happens downstream), making `Weight = HOLISTIC_ORIGINAL_W·WOriginal + HOLISTIC_REGULAR_W·WRegular` (under the D1 ruling: `1.0·WOriginal + 0.2·WRegular`) exactly recomputable on the base file. Rows must be emitted even when a role dial is 0 — dropping zero-weight rows would destroy the re-weighting basis. **Scope this claim honestly:** the identity holds on the BASE vintage only. The engine-consumed AUG vintage folds in non-cosponsor layers, symmetrizes, and applies social reinforcement — none of which is role-separable — so a D1 re-ruling is: recompute the base weights artifact-side, then **re-run the (in-repo, minutes-scale) augmenter**. Never a re-collection; also never a pure edit of the AUG file. The two vintages carry different schemas by design: BASE = 8 columns + `WOriginal`/`WRegular`, directed; AUG = Edges (3-col) + Provenance, symmetrized. So:

- D1 re-rulings are a base-side recompute plus an augmenter re-run, never a re-collection;
- per-layer scope labels (§4.2) travel with the artifact;
- the network-viz backlog request (layer toggles) gets its *artifact-level* data — note that surfacing full-graph layer toggles in the UI still requires extending the bundle's provenance channel, which today covers only the top-420 drawn edges (`elay`), a D7-adjacent work item, not a freebie.

The holistic *augmenter* is the same code path as today's, parameterized: run `build_multilayer_network.py` logic against the holistic base with the same kernel-inverse mapping, caps, floors, isolates-only HCoI rule, and social reinforcement — "same methodology" is literal: same formulas, same dials, different universe and an extra co-appearance layer (D2).

## 6. Things to keep in mind (risk register)

**6.1 The selection trap (highest-severity code risk).** Any filename matching `congress_cosponsor_network_*.xlsx` participates in implicit mtime selection — for the AUG-preferring engine loader, for the non-AUG-preferring directed loader, **and — the worst victim — for the weekly-refresh augmenter itself**, which picks its augmentation *base* as the newest non-AUG glob match (`build_multilayer_network.py:31-32`): a glob-matching holistic file would be silently folded into the production CU AUG artifact at the next weekly refresh, contaminating the *default* config for every consumer. The holistic family name must fail that glob entirely (§4.1), the builder should assert it at write time, and Phase 3's regression covers the read side and the write side both. The shadow lane's ambiguity error is the model.

**6.2 Kernel scale under density change.** `p = w/(w+6)` makes a weight-6 tie ≈ 50% activation; the constant 6 is a chosen scale anchor that sits against CU-universe weight sums (the augmenter's "cap 2.0 ≈ a strong cosponsor tie" comment is the only in-repo scale provenance — there is no recorded tuning run). The back-of-envelope — **a labeled envelope, not a measurement** — says the holistic base is denser and heavier than the CU baseline under any cosponsorship weighting. Illustrative point (assumptions stated: role 0.5, SUCCESS 1.0, one congress of decay 0.8, C=4, `cpf`=σ_v=1 — the same-party, receptivity-neutral slice of the full kernel `p = w·cpf·σ_v/(w·cpf·σ_v+6)`): a per-bill tie contributes ≈0.2, so p = 0.5 needs on the order of 29 shared bills at that rate (fewer for originals at ≈0.4/tie, more for D1-priced regulars at ≈0.08/tie, and more still cross-party where `bpf` discounts). That bill count is essentially unreachable inside the 17-template CU universe — whose AUG20260802 graph carries 2,555 roster-internal edges out of 141,778 possible member pairs, ≈1.8%, per the 2026-08-17 structure-probe record; note that figure is the *multiplex* count, so cosponsor-only density is lower still, which strengthens the contrast — but plausible for close dyads over an all-bills 117–119 universe where frequent collaborators share dozens to hundreds of ties. Phase 5 replaces this envelope with measured distributions before anything is concluded. **Saturation is the operative direction of risk** (dense pairs pushed toward p→1, which flattens max-product path discrimination and inflates IC reach — exactly where the pathfinders live); the envelope motivates measuring it, Phase 5 establishes it. **Do not retune the kernel constant** — it is hardcoded in three places (`build_P`, the augmenter's kernel-inverse, and the JS mirror's `PEBASE`), all shared with the CU config. Instead: measure the holistic distribution (Phase 5) and, if the **induced p-distribution** diverges materially (median *and* tail mass above p=0.5/0.8 — a weight-median match alone can leave the tail saturated), apply a single documented `HOLISTIC_WSCALE` factor at the builder. Be clear-eyed about what that is: algebraically `s·w/(s·w+6) = w/(w+6/s)`, so WSCALE *is* a per-config kernel constant — placed artifact-side precisely so it cannot leak into the CU config and so the JS mirror inherits it through the serialized weights with zero template edits. The flip side of that invisibility: an operator reading "weight 6 ≈ 50%" against a scaled holistic artifact would misread every weight, so **the holistic manifest carries the effective scale in-band** (`wscale: s`, effective kernel constant `6/s`) and any surface that prints holistic weights prints the scale with them. A single scalar cannot fix distribution *shape*; if the tail still saturates after matching the median, that is a named Phase-5 finding for Paul (**D8**), with a concave transform or cap as the explicitly-forked alternative. (Scoping note: the E3 probe's "degenerate on sparse network" finding is a *clustering-distance* failure — the Zhan-Cai/SNGDM machinery presuming dense pairwise matrices — and is the standing adverse prior for any community/consensus analysis run on the sparser non-cosponsor layers; it is not a cascade-kernel concern.)

**6.3 One writer / two configs.** The weekly refresh writes the CU family; the holistic build is a separate, serialized step (never concurrent with the refresh — OneDrive locks and the one-writer law). Chain placement decision (weekly vs on-demand) rides D7.

**6.4 Memoization.** `_c['adj']` is process-global. Config-keyed caching (§4.1) is mandatory before any script can touch both graphs; without it, audit scripts comparing configs would silently compare one graph to itself.

**6.5 JS mirror drift.** Every JS pathfinder reads the serialized bundle; the mirror is hand-maintained with no audit coverage. v1 keeps holistic off the live surfaces (separate labeled bundle), which contains the drift risk instead of doubling it.

**6.6 Language discipline.** The FEC×LDA R3 ruling stands: structure-derived findings get descriptive language only — no predictor claims from network structure. Citations stay honest-analogical (RELINK/GCOMB/D*-Lite name mechanisms, not validations — D*-Lite in particular is a cited principle, not an implementation). Every figure in holistic reports names its window and denominator in-sentence (Claims constraint).

**6.7 Scope discipline.** Signed edges stay out of the unsigned kernel (no invented negative magnitudes — the Bakker clamp precedent). Hearing co-location stays excluded (settled design, not a bill guard). Ranks, bipartisanship, stance, and the say-do gate do not consume the holistic graph without an explicit ruling (§4.6). Worktrees don't isolate the data plane — builds and verification run in the live tree, and importing `fec/*.py` executes against live data.

**6.8 External dependencies stay external for now.** Press/HCoI holism requires re-collecting an all-topic press corpus (external R pipeline) — a separate, larger campaign. The guide deliberately ships partial holism with per-layer scope labels rather than blocking on it.

**6.9 Rollover.** The 120th Congress seats 2027-01-03; congress dials and the roster gate must take the rollover as config, and the 2026 primary upsets already noted by the recon lane (incumbency re-derivation; brain STATE.md, recorded 2026-08-17) will land inside this window.

**6.10 "Same methodology" is not the same behavior on a dense base.** The augmenter's admission rules are keyed to base-graph *sparsity*: engagement and social add new edges only for **untied** pairs, and HCoI admits only edges touching a **cosponsor-isolated** member. On an all-bills base, isolation largely vanishes (members who never cosponsor CU bills still sponsor and cosponsor plenty of bills) and most press/social pairs are already tied — so run unchanged, the HCoI layer contributes approximately zero edges, engagement and social collapse into the reinforcement branch, and a promoted co-appearance layer adds little through an untied-only branch. The holistic multiplex would quietly degenerate to cosponsorship-plus-reinforcement. This is a fork to surface, not to smooth over — and it is on the menu as **D10, decided *before* Phase 3 builds the augmenter**, not discovered as a Phase-5 surprise: choose per layer between (a) keep the untied-only/isolates-only rules and accept vacuity where it lands, or (b) a weight-dominance rule such as `max(base, layer)` in the holistic config — an explicit departure from "same methodology." One interaction to rule with eyes open: option (b) re-injects the *CU-corpus* press/HCoI layers onto an all-bills graph, i.e. CU-scoped mass inside "holistic" weights — permissible only as a labeled, ruled choice (D9's scope table must then show it), never as a silent admission tweak. Phase 5 still reports per-layer admitted-edge counts (CU vs holistic) to check the ruling against reality.
